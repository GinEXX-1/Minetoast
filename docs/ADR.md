# Architecture Decision Record · Phase 0

状态约定：以下决定由本轮架构工作确定为 proposed baseline，等待用户确认进入 Phase 1；更改须新增 ADR 说明替代关系，不覆盖旧决定。日期 2026-09-06。

## ADR-001 — 模块化单体与客户端画布

背景：主要价值是知识图探索，无 SSR/SEO 的强制要求，团队需要可长期维护的明确边界。
决定：React/Vite 前端、Fastify API、共享 TypeScript 契约，pnpm workspace；同源部署。
备选：Next.js 全栈、微服务。取舍：少框架隐含状态，API 可独立测试；需自己维护路由与鉴权，跨应用发布要保持契约兼容。
重审条件：出现公开内容 SEO 或服务拆分的实际需求。

## ADR-002 — PostgreSQL 关系图与 SQL 唯一事实源

背景：输入明确 PostgreSQL、不引入 Neo4j，节点规模约 400。
决定：节点和边关系表、外键和唯一约束，pg 参数化 SQL；JSONB 只放嵌套内容与发布快照。
备选：Neo4j、图数据整包仅 JSON、ORM schema 双维护。
取舍：事务、进度和内容在一库，SQL 可复审；DAG/语义审核不能只靠 CHECK，须发布门。
重审条件：规模或图查询成本经测量无法满足需求。

## ADR-003 — 掌握事实与可用状态分离

背景：非级联撤销与三状态若一起持久化会发生冲突。
决定：user_unlocked_nodes 行存在即掌握；Locked/Available 由当前 Strong 图推导；掌握事实优先。source 枚举替代多个互斥布尔值。
备选：每用户×每节点存完整三态。
取舍：不丢后继自评事实；渲染时需投影，数据库不能单列查询所有 available 而不结合图。
重审条件：出现正式测评与自评双轨，应新增 evidence 模型，不能直接改变本语义。

## ADR-004 — DAG、审核与不可变发布

背景：直接编辑 live 边会即时改变学习状态；未知依赖不能当真。
决定：编辑表作为草稿；全 enabled 图 DAG；Strong 严格传递约简；未审核 enabled 依赖阻断发布；完整快照不可变，head 原子切换。
备选：学生直接读编辑表；仅 Strong 无环允许 Weak 环；自动过滤未审核边。
取舍：多存一份快照，换取内容一致性与回滚；Weak 必须定向无环可能限制一般关联表达，未来非先修关联另建类型。
重审条件：业务明确需要无向/互相关联，或全图快照尺寸超出合理预算。

## ADR-005 — 原子、幂等进度命令

背景：快速初始化、重试和多标签页可能重复点亮/丢失更新。
决定：head 固定版本 + 用户行锁 + expectedRevision + idempotencyKey，进度/事件/结果在单事务提交；初始化仅强祖先，撤销仅自身。
备选：前端递归后逐节点请求；无版本最后写胜出。
取舍：事务契约稍复杂，但可确定恢复网络失败，不会半批更新；用户操作按序提交。
重审条件：真实多设备离线编辑需求出现，再评估同步合并。

## ADR-006 — XYFlow + ELK Worker + 人工覆盖

背景：原文要求 React Flow，大型多父节点 DAG，用户不可拖乱结构。
决定：XYFlow 只渲染；ELK layered 仅在拓扑/尺寸/版本改变时布局；人工覆盖最后应用；纯 graph-core 处理算法。
备选：Dagre、Pixi/Canvas 自研。
取舍：先利用成熟 DOM 交互与可访问性；复杂图仍需测量和局部渲染，手工覆盖后的碰撞需审核。
重审条件：合成图与实际数据的性能验收均不达标且常规优化无效。

## ADR-007 — 全局路径图与门户投影

背景：跨域先修不能因 Tab 隐藏而丢失。
决定：全局图计算解锁与路径，领域视图局部投影；Portal 不属于数学节点；Between 展示全部有效 Strong 路径并集。
备选：每领域独立图；Between 仅最短路径。
取舍：避免漏先修；跨域路径需临时全局视图，也需说明路径外额外前置。

## ADR-008 — 账户云进度与只读游客

背景：PRD 明确游客浏览自由、个人进度需登录。
决定：username/password、数据库会话、Cookie、CSRF、角色校验；游客无本地掌握数据；JSON 导入默认 merge。
备选：游客 localStorage 后注册合并、OAuth-first。
取舍：符合 V1 范围，避免同步冲突；用户名密码带来密码恢复与限速维护工作。

## ADR-009 — 资产与内容分离

背景：350 个图标逐个生成成本高，字体音效有授权前提。
决定：按领域 Sprite Sheet、人工检查后裁切；资产不可变版本、来源/许可记录与发布门；图像文字/公式分层；合法占位可先行。
备选：逐节点三状态独立图、二进制塞数据库、覆盖 CDN 同 URL。
取舍：风格与缓存可控；AIGC 网格不保证精确，需要人工校图。本轮零生成。

## ADR-010 — 性能与数学正确性门槛

背景：快速初始化容易 Toast 风暴，图渲染流畅不代表知识科学。
决定：初始化禁止 Toast/重粒子；性能合成图与数学内容验收分开；真 PostgreSQL 并发测试；函数单域切片过门后再扩张。
备选：一次铺全量 350 节点、只靠视觉冒烟验收。
取舍：较晚获得完整世界，但每次扩张有可复用的验证基础。

## ADR-011 — Knowledge Dependency Quality Gate 取代逐项人工签审硬门

背景：逐项外部人工签审会把所有节点和边绑定到单一人工瓶颈，也不能保证依赖的必要性判断一致。教材引用和图结构检查本身都不足以判断一个概念是否是另一个能力的必要前置。
决定：每条 Dependency 记录 Canonical Textbook Evidence、数学定义、反事实前置测试、图谱结构上下文和 rationale，并输出 `KEEP_STRONG`、`DOWNGRADE_TO_WEAK`、`REMOVE` 或 `REVIEW_REQUIRED` 与 `HIGH`、`MEDIUM`、`LOW` confidence。完整且无冲突的 `HIGH` 自动通过；`MEDIUM` 需两次独立 AI Review 一致；`LOW`、证据冲突、定义歧义或 AI 冲突进入 `REVIEW_REQUIRED`。未通过的依赖不作为有效边发布，不阻断无关的已通过候选。人工 override 仍可记录，但不是所有内容的强制门。
边界：Graph Validator 继续校验 DAG、cycle、orphan、transitive redundancy、overconnected 和重复边；其结果不用于推断数学必要性。结构性 orphan 作为发布报告 warning，不能把待决依赖自动转为 Strong。
备选：保留所有节点/边的人工签审硬门；仅依据教材章节顺序自动推导依赖。取舍：前者吞吐量低，后者缺乏数学有效性；新门禁引入 AI Review provenance 与冲突处理成本，但保留可审计结论。
重审条件：出现可验证的外部教研工作流、AI Review 质量无法满足抽检要求，或图谱规模使每边双轮 Review 成本不可接受。

## ADR-012 — Phase 2B候选隔离及独立评审一致性

日期：2026-09-24。P2A本体和P1回归数据冻结，P2B另存提案、独立review和有效edge seed；外部基础与范围未定节点保留记录，但不伪装为active DAG的无前置root。候选包不直接发布。
独立评审一致指依赖决定一致；MEDIUM与HIGH的一致意见按较保守MEDIUM处理。LOW、不同决定、证据冲突或定义歧义仍进入REVIEW_REQUIRED。HIGH判断须先检查已有review冲突，不能提前短路放行。此规则细化ADR-011，并取代旧说明中的“置信度必须逐字一致”；保留P1审核记录原文作为历史，不回写其结论。
完整关系路径使用独立的includeWeak遍历，解锁与快速初始化固定使用Strong索引。本轮提供离线模拟，不切换在线图或实施Phase 2C。
