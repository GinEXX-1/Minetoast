# 创作指南

1. 确认节点知识定义与教材边界，评估 HIGH/MEDIUM/LOW/NONE。第一版仅为 HIGH 创作。
2. 选教学模式，规划 3–8 步、30–180 秒。写完整 semanticLabel 和极简 caption。
3. 选 renderer，用数学对象/表达式/约束表达现象。避免预录媒体或节点特定组件。
4. 先运行 `pnpm ponder:validate`。检查参数端点、退化情况、公式条件和交互数学不变量。
5. 通过真实浏览器观察桌面、平板和紧凑尺寸，检查文字/图像、键盘、减少动态效果、退出焦点、WebGL 相机及性能。截图既是审核材料，也应成为基准回归证据。
6. 创作者提供严格 Schema 的场景 JSON，由不同身份的审查者核对数学、教材与渲染证据。没有 AI 生成或模型服务依赖。
7. 新场景首先作为候选，不能未经审查直接进入生产。附带绑定 digest 的九维证据及真实独立审核，执行严格 gate；PASS 后由发布服务决定落库。

当前目录中的 8 个场景由本次工程实现手工创作，处于本地试运行，status=REVIEW_REQUIRED。正式教材签审不由本地测试自动替代。新增场景优先验证 renderer 通用性，而不扩展 350 个节点。

圆切线 Pilot 暂挂在既有 `HS-GEO-CIRCLE-EQUATION-001`，避免改变 Phase 2 内容/依赖；入口标题为圆的标准方程，演示标题为圆的切线。若之后需要独立圆切线节点，应走原知识内容审核流程。

参数 a=0、k=0 明确标为退化情形。导数场景保证 h>0，有限差商不会冒充极限或导数。Plot 的断开采样只是表示策略，不是自动证明奇点的位置；创作者需要分离已知不连续分支。

## 动画编排

先写 show 快照，再为新对象安排 draw/reveal，为本步推理所需关系安排 pulse。参数变化需留出对象构建时间，不能让字幕、标记、参数与真实数学关系冲突。每步都应有明确观察动作；仅切换字幕不满足要求。使用 narration 延后符号表达，提供完整 semanticLabel。运行 `pnpm ponder:storyboard` 检查演出顺序，再验证播放/暂停/回放的前中后截图。新增节点只修改 DSL，渲染器不得按 nodeId 分支。
